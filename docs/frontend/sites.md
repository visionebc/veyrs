# Product site and documentation site builders

VEYRS publishes two static sites. Both are generated by Python scripts that use **only the standard library**, so the public-facing host stays reproducible and auditable (`site/build.py:4-5`, `site/web/build_web.py:9-11`). Neither runs at request time; nginx serves the output directory.

| | Docs Center | Product site |
|---|---|---|
| Generator | `site/build.py` | `site/web/build_web.py` |
| Default `--out` | `/var/www/veyrs` | `/var/www/veyrs-web` |
| Input | Every `*.md` directly under `docs/` and every `docs/ADRs/*.md`; `site/static/` | Page functions in the script, strings in `site/web/i18n/`, styles in `site/web/assets/`, plus two Markdown files (`docs/USER_MANUAL.md`, `docs/DOCKER_COMPOSE_MANUAL.md`) |
| Audience | Engineers and operators (internal; `noindex,nofollow`) | Evaluators and operators (the public-facing site) |
| Served by | The `default_server` vhost of an application node | Its own vhost (`try_files $uri $uri.html $uri/ =404`, `/assets/` cached 7 days) |

> [!NOTE]
> The nginx vhosts of both sites are in the repository since 0.41.0: `infrastructure/nginx-veyrs-docs.conf` and `infrastructure/nginx-veyrs-web.conf`. See [operations/services.md](../operations/services.md).

> [!IMPORTANT]
> `site/build.py` was rewritten as the documentation portal during this documentation work: in the source tree described here (0.39.1 plus the portal) it is 1,058 lines, parses YAML front matter (`parse_front_matter`, `site/build.py:123`), discovers every Markdown file in every sub-folder of `docs/` (`discover`, `:447`), files each one into one of 14 domains (`DOMAINS`, `:47`) and links the pre-rendered SVG of each Mermaid block (`mermaid_hash`, `:199`). The builder shipped in release 0.39.0 (498 lines; the 0.39.1 changelog lists no change to it) did none of this. The three flags (`--out`, `--site-url`, `--console-url`, `:1052-1054`) are the same in both. Statements below marked *baseline* describe the 498-line builder and no longer hold for the portal.

## Shared renderer

`site/build.py` contains the Markdown renderer (`render(md)` returning `(html, toc)`); `site/web/build_web.py` imports it (`from build import render as render_markdown`), so a document renders identically on both sites. It supports a deliberately small subset: headings, paragraphs, lists (wrapped items stay one item), pipe tables, fenced code, blockquotes, bold/italic/code/links. In the *baseline* it had **no front-matter support** (a leading `---` block rendered as a rule and a paragraph) and no Mermaid support; the portal builder strips front matter and, in `rich` mode, replaces each Mermaid block with its pre-rendered SVG (`render(md, rich=False)`, `:308`). `tests/test_site_render.py` fails if any doc leaves stray `>`, fences or `**` on the page.

The Docs Center navigation bar is the product site's own `NAV`, read from `build_web` at build time (`site_nav()`, `site/build.py:604`), so the two bars cannot drift.

## Product site (`site/web/build_web.py`)

Redesigned on 2026-11-24 (design decisions: `site/design-system/veyrs-web/MASTER.md`). Five locales, no JavaScript, self-hosted fonts.

### Usage

```bash
# On an application node, as a user that may write the document root, from the checkout
cd /opt/veyrs
python3 site/web/build_web.py \
    --out /var/www/veyrs-web \
    --console-url https://veyrs.example.com \
    --docs-url https://docs.veyrs.example.com
```

| Flag | Default | Effect |
|---|---|---|
| `--out DIR` | `/var/www/veyrs-web` | Output directory (created, with `assets/` and one directory per non-English locale) |
| `--console-url URL` | env `VEYRS_SITE_CONSOLE_URL`, else the reference-environment console | Target of every "Open the console" link (navigation button, hero, closing band, footer) |
| `--docs-url URL` | env `VEYRS_SITE_DOCS_URL`, else the reference-environment Docs Center | Target of documentation links on the LAN build |
| `--site-url URL` | env `VEYRS_SITE_URL`, else the reference-environment product site, or `https://veyrs.example.com` with `--public` | Absolute base of the `canonical`, `hreflang` and Open Graph URLs |
| `--public` | off | Internet-facing build: every documentation link goes to the Markdown on the public GitHub mirror (`<REPO_URL>/docs/<slug>.md`, or the mirror file listed in `DOC_TARGETS`) instead of `--docs-url`, which only resolves on the LAN; "Documentation on GitHub" points at the mirror's `docs/` tree |
| `--webfonts self\|google` | `self` | `self` copies the console's fonts (`frontend/console/fonts/`) to `assets/fonts/` and links `assets/fonts.css` (needs CSP `font-src 'self'`); `google` links Google Fonts instead, for a host whose CSP still only admits `fonts.gstatic.com` |

The defaults are module globals reassigned by `main()` before the build loop, because the same source builds the site for more than one environment (a production visitor must not be sent to a pre-production console). The script prints the page count per locale, the CSS hash and the console, docs and site targets it used.

### Locales

| Locale | Directory | Strings |
|---|---|---|
| English (source) | site root | `site/web/i18n/en.json` |
| Spanish, German, French, Italian | `/es/`, `/de/`, `/fr/`, `/it/` | `site/web/i18n/<lang>.json` |

Every visible string is a key in the JSON files (values are trusted HTML fragments with `<b>`, `<code>`, ...; `{n}` and `{packages}` are filled at build time). Host names, commands and product names stay in the script. Each locale holds the same eight pages; every page carries `<html lang>`, `canonical`, `hreflang` alternates for the five locales plus `x-default`, `og:locale`, and a language switcher (a `<details>` disclosure in the navigation, a list in the mobile menu and in the footer) that keeps the reader on the same page. The two manuals stay English in every locale (the repository's documentation policy): their article carries `lang="en"` and, outside English, a localized notice with a link to the English page. `tests/test_site_i18n.py` fails on a missing key, a changed tag or code span, a lost placeholder, or a value left identical to English unless the locale lists the key in `_identical_ok` (or the value is only brand and standard terms).

### Output (per locale)

| File | Page | Content |
|---|---|---|
| `index.html` | VEYRS | Hero (positioning, value statement, console call to action, illustrative decision-queue panel marked as such, the Visibility → Exposure → Risk → Action → Security chain); standards and compliance frameworks; the problem and a severity-versus-risk comparison; how it works (five steps); capabilities; principles; security and trust; deployment options; closing call to action |
| `features.html` | Capabilities | Ingestion (the format count is read from the two parser registries at build time); Execution; Threat intelligence; Risk-based prioritisation; Ticketing and SLA; Reporting and compliance |
| `architecture.html` | Architecture | Topology (HTML diagram); Why the application nodes hold no state; Scheduled jobs run on exactly one node; What each failure costs; Data protection; Promotion is manual on purpose; Stack (pinned-package count from `requirements.txt`) |
| `security.html` | Security | Tenant isolation; Authentication; Secrets; Untrusted input; The agent authorisation model; Observability endpoints; Supply chain |
| `download.html` | Download | Get the release (signature check, then `sha256sum -c`, then the installer); Permissions; Network; Hardware (thresholds restated from `veyrs-setup.sh`, kept in step by `tests/test_site_render.py`) |
| `docs.html` | Documentation | The documentation hub: user manual, installation, architecture and availability, security, API reference, the full documentation (Docs Center on the LAN, the GitHub `docs/` tree in public); "Which document do I need?"; the core-document library; the ADR index |
| `manual.html` | User manual | `docs/USER_MANUAL.md` rendered, with an "On this page" rail of its `##` headings |
| `install.html` | Installation with Docker Compose | `docs/DOCKER_COMPOSE_MANUAL.md` rendered, same layout |
| `assets/web.css`, `assets/fonts.css` | | Copied from `site/web/assets/`; pages reference them as `?v=<first 10 hex of the SHA-256 of both>` |
| `assets/fonts/` | | The console's font files, copied at build time (never committed twice) |
| `assets/` brand files | | Copied from `site/static/`: `veyrs-logo-on-dark-gradient.png`, `veyrs-mark-gradient.png`, `veyrs-favicon.ico`, `veyrs-favicon.png`, `veyrs-tokens.css` |

The navigation has five entries (`NAV`: Capabilities, Architecture, Security, Download, Documentation) plus the language switcher and an "Open the console" button; the brand mark links the home page, and the footer links every page, both manuals, the API reference and the Docs Center. Every URL of the previous site (`manual.html`, `install.html`, `docs.html`, `download.html`, `features.html`, `architecture.html`, `security.html`) still exists. The page `<title>` is `<Page> — VEYRS` (the home page is `VEYRS — <tagline>`, never "VEYRS — VEYRS").

### Link rules

- A body names a doc as `href="doc:SLUG"`; `_doc_links()` resolves it at build time through `doc_href(slug)`.
- `LOCAL_DOCS` maps two slugs to pages of this site (`USER_MANUAL` -> `manual.html`, `DOCKER_COMPOSE_MANUAL` -> `install.html`); `DOC_TARGETS` maps Docs Center pages that are not top-level docs (API guide, installation, ADR index) to their LAN path and to the mirror file that covers them; every other slug goes to `--docs-url` (`<docs-url>/<slug>.html`) or, with `--public`, to the GitHub mirror.
- Links inside the two embedded manuals are relative to `docs/` in the repository. `_repo_links()` sends `docs/<NAME>.md` through `doc_href()` (the Docs Center on the LAN, the mirror in public) and every other repository path to its GitHub `blob/main` URL; absolute, `#` and `/` links are left alone.
- Guard tests (`tests/test_site_render.py`, `tests/test_site_i18n.py`): every relative link of either build resolves to a built file, every page exists in every locale with the full `hreflang` set, the public build names no LAN host, no `doc:` placeholder survives, and every mirror link names a file that exists in the repository. The public mirror is only refreshed by a release, so check a new mirror link with HTTP before a public deploy.

## Docs Center (`site/build.py`)

### Usage

```bash
# On an application node, from the checkout
cd /opt/veyrs
python3 site/build.py \
    --out /var/www/veyrs \
    --site-url https://veyrs-web.example.com \
    --console-url https://veyrs.example.com
```

| Flag | Default | Effect |
|---|---|---|
| `--out DIR` | `/var/www/veyrs` | Output directory |
| `--site-url URL` | reference-environment product site | Base of the navigation links to the product site and the footer "Product site" link |
| `--console-url URL` | reference-environment console | Target of the "Console" button and footer link |

The source-repository link in the footer (`SOURCE_URL`) and the version in the footer (read from `pyproject.toml`, `_version()`) are not flags.

### What it builds

For every `docs/<NAME>.md` (and `docs/ADRs/<NAME>.md` under `adr/`) it writes `<NAME>.html` with: the site chrome (skip link, navigation bar, page band whose `<h1>` is the document's own first heading moved out of the article), a sidebar listing every document by category, an "On this page" rail from the headings, and a footer. It also writes:

| Output | Purpose |
|---|---|
| `index.html` | Home: one card per category, every document with its first-paragraph summary, and a search box |
| `search.html` | Search page; `static/veyrs.js` fetches `/search-index.json` and filters it in the browser (every term must match; title and heading hits rank higher). The page says JavaScript is required |
| `search-index.json` | One record per page: title, URL, category, summary, headings, first 4,000 characters of plain text |
| `static/` | A wholesale copy of `site/static/` (`veyrs.css`, `veyrs.js`, logos, favicons, `veyrs-tokens.css`). The existing `static/` is deleted first (`shutil.rmtree`) so a removed asset does not linger |
| `static/fonts/`, `diagrams/` (portal builder) | The console's self-hosted fonts copied from `frontend/console/fonts/`, and the Mermaid SVGs the pages use. Both directories and every per-folder page directory are deleted and rebuilt on each run (`site/build.py:775-792`), so pages of an older layout do not linger |

Category filing: in the *baseline* it was the `NAV` list (Start here; Requirements & architecture; Design & brand; Install & operate; Security; Engineering) and only files directly under `docs/` (plus `ADRs/`) were discovered. In the portal builder it is `DOMAINS` (`site/build.py:47`): 14 domains, each matching explicit keys or folder prefixes (for example `audit/`, `internal/` filed under *Install & operate*); `NAV` is kept only as a compatibility view. A document that matches nothing still builds, under **Other**, and `tests/test_docs_center.py::test_every_document_is_filed_in_a_domain` fails until it is filed.

Page assets are cache-busted with `?v=<hash of veyrs.css + veyrs.js>` (`_asset_version()`). The Docs Center deliberately does **not** link `veyrs-tokens.css` (its OS-dark block redefined `--text` and `--border` and blanked the text in dark mode, 0.38.3) but still ships the file in `static/` because the console reads it from there.

## Publishing

There is no deployment step in the installer for either site, and no CI job in the repository: both are rebuilt by hand into the local document root on **each application node** after a documentation change (`docs/HIGH_AVAILABILITY.md`: "they are interchangeable only because both nodes sit on the same commit and both run the builders").

```bash
# On EACH application node, as root, in the checkout (default /opt/veyrs)
cd /opt/veyrs
git pull
python3 site/build.py --out /var/www/veyrs \
    --site-url https://veyrs-web.example.com --console-url https://veyrs.example.com
python3 site/web/build_web.py --out /var/www/veyrs-web \
    --console-url https://veyrs.example.com --docs-url https://docs.veyrs.example.com
```

Verify both nodes by building into a temporary directory and comparing the tree with the docroot (`docs/TESTING_GUIDE.md`, release check 5):

```bash
# On each application node
cd /opt/veyrs
python3 site/build.py --out /tmp/veyrs-docs-check
diff -r /tmp/veyrs-docs-check /var/www/veyrs && echo identical
```

> [!WARNING]
> `site/build.py` removes and re-copies `<out>/static/` while it runs, and the host console vhost aliases `/static/` to that directory. During the few moments of a rebuild a console page load can miss `veyrs-tokens.css`. It also never deletes stale `*.html` files, so a document removed from `docs/` stays served until deleted by hand.

The console is deliberately **not** built by either script: it is three copied files (see [README.md](README.md)). The two are coupled only through `/static/`: on a host install the console's `/static/` is the Docs Center's `static/` directory.

## Known differences between the sites

| Topic | Docs Center | Product site |
|---|---|---|
| Fonts | The console's self-hosted Inter and JetBrains Mono, copied at build time | The same files, copied to `assets/fonts/` at build time (`--webfonts self`); the vhost's CSP is `font-src 'self'` |
| Scripts | `veyrs.js` (sidebar toggle, scroll-spy, search) | None: menus are `<details>` elements; the vhost sets `script-src 'none'` |
| Colours | `site/static/veyrs.css` | Variables at the top of `site/web/assets/web.css`, taken from the brand tokens (`docs/BRAND.md`) |
| Colour scheme | Light and dark (toggle) | Light content with deep-navy bands (hero, page heads, principles, footer) |
| Languages | English | English, Spanish, German, French, Italian (manuals in English) |
| Indexing | `<meta name="robots" content="noindex,nofollow">` on every page | No robots meta tag; `canonical` and `hreflang` on every page |

The design rules for the three palettes are in [DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md).
