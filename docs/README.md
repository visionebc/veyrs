# VEYRS

**Unified Cybersecurity Risk Management**

VEYRS is not a vulnerability scanner or a vulnerability dashboard. It is the
spine that connects the things a security programme already has but cannot join:

```
CVE -> Product -> Version -> Asset -> Criticality -> Exposure -> EPSS ->
CVSS v4 -> KEV -> Threat Intelligence -> VEYRS Risk -> Responsible Team ->
Ticket -> SLA -> Escalation -> Change -> Remediation -> Verification ->
Compliance Evidence -> Audit
```

That chain is the product. Everything below exists to make it traversable in
both directions, in one query, per tenant.

## What makes it different

**1. Risk, not severity.** CVSS is an input, not the answer. The engine combines
CVSS v2/v3/v4, EPSS, CISA KEV, asset criticality, internet exposure, data
classification, business service and vulnerability age into four sub-scores and
one defensible number - with a stored explanation of every factor that moved it.

**2. A CVSS engine that is actually correct.** v2, v3.0, v3.1 and v4.0 are
implemented from the published algorithms, not approximated. Validated against
**4,382 official vectors** from FIRST's reference implementation. v4 uses
half-up rounding, because Python's default banker's rounding moved 43 of them.

**3. AI that cannot exceed the user.** Every capability maps to a permission the
caller must already hold. Confidential data cannot reach an external provider
under default policy. Secrets and PII are stripped before any model sees a
prompt. The model proposes structured output; VEYRS validates it against a
closed grammar and compiles the query itself.

**4. Honest compliance.** Catalogues ship as identifiers and titles only, with
the copyright position stated, and every coverage report carries a disclaimer
that cannot be turned off. An automated signal can lift a control to *partial*,
never to *implemented*.

**5. Imports that refuse to guess.** A scanner record whose asset cannot be
identified is rejected with a reason - never attached to a plausible neighbour.
A finding absent from an export is a stale candidate, not a closure.

**6. Numbers that show their working.** Every ratio ships with its denominator;
every average with its sample size and a reliability flag.

## Quick start

```bash
curl -X POST https://veyrs-docs.example.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"...","organization":"acme"}'

curl https://veyrs-docs.example.com/api/v1/dashboard/executive \
  -H "Authorization: Bearer $TOKEN"
```

## Stack

FastAPI · SQLAlchemy 2 · PostgreSQL 15 (Row Level Security) · Redis ·
Argon2id · Fernet · reportlab · openpyxl. Optional: OpenSearch, Qdrant, Ollama.

Deployed either by `install.sh` (one script, Debian/Ubuntu · openSUSE/SLES ·
RHEL/Rocky/Alma) or by the container stack in `docker/` — see
[Architecture §14](/ARCHITECTURE.html).

The documentation site you are reading is generated by a 250-line standard
library script with **zero third-party dependencies** - a security product's
public host should not drag in a dependency tree that then needs auditing.
